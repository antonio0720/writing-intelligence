# Corpus Governance Engine — Pass 2

**Purpose**: Prevent source confusion, hallucinated context, and accidental blending of unrelated material.

**Schema**: `schemas/corpus_map.schema.json` (`CorpusMapV3`)

**Agent**: Corpus Auditor (`agents/corpus_auditor.md`)

---

## The Problem v3.0 Solves

In v2.0, when a user pasted three documents and asked for "a summary that uses all of them," the compiler treated everything as undifferentiated context. Sources blurred. Stale data drifted into fresh drafts. Memory contaminated new work. Generated ideas got cited as facts.

v3.0 forces explicit source layering. Every passage in the output can be traced to a source ID, a source type, and a source status. If a claim has no source, the Evidence Prosecutor (Pass 5) will catch it.

---

## Source Types

| Type | Definition |
|---|---|
| `user_text` | Text the user provided in this session as primary material |
| `repo_knowledge` | Doctrine and references from this skill |
| `external_document` | Files the user attached |
| `prior_memory` | Project memory from prior sessions |
| `example` | Reference example, never to be cited as fact |
| `generated_idea` | Idea generated by the compiler in this session; never citable |
| `web_fetch` | Live web fetch result |
| `user_provided_data` | Structured data the user supplied (CSV, tables, JSON) |

---

## Source Status

| Status | Meaning | Allowed in Output? |
|---|---|---|
| `verified` | Confirmed against a trustworthy source | Yes |
| `user-provided` | User asserted it; truth-value not independently verified | Yes, with attribution |
| `assumed` | Reasonable assumption; should be flagged | Yes, qualified |
| `inferred` | Derived from other claims | Yes, with chain marked |
| `missing` | Required but absent | Halts ledger; surfaces to user |
| `unsafe` | Known to be wrong, stale, or risky | **Blocks delivery** |
| `stale` | Was true; freshness expired | Flag; user decides |
| `contradictory` | Conflicts with another higher-priority source | Resolve before output |

---

## Priority Order

Sources are ordered. When two sources conflict on the same fact, the higher-priority source wins. Default order:

1. User text (current session)
2. User-attached external documents
3. Verified web sources (when fetched live)
4. Prior project memory
5. Repo knowledge
6. Examples (never used as authority)
7. Generated ideas (never used as authority)

The user can override this order in the intake contract.

---

## Conflict Resolution

When sources conflict, the engine emits a `conflicts` entry and chooses one of:

- `a_wins` — higher-priority source wins
- `b_wins` — explicit user choice
- `merge` — both perspectives included, attributed
- `flag_for_user` — pause and surface
- `block` — refuse delivery until resolved

---

## Fabrication Detection

The Corpus Auditor maintains a `fabrication_risks` list — every claim in the draft that would require fabrication if no source is added. Pass 5 must resolve each entry (find a source, soften the claim, or remove it).

Hard-block triggers:

- Invented statistics or quantities
- Invented studies, papers, court cases, scripture references
- Invented quotes attributed to real people
- Invented institutional names
- Invented dates
- Invented monetary figures
- Invented historical events

---

## Memory Hygiene

When `memory_allowed` is true (Pass 0), the Corpus Auditor:

1. Loads applicable entries from `references/compiler/memory_system.md` plus any storyworld memory.
2. Stamps each memory entry with its freshness timestamp.
3. Marks any entry older than the freshness threshold as `stale`.
4. Excludes any entry tagged `unsafe`.

## Definition of Done

The Corpus Auditor produces a corpus map that:

- Validates against `corpus_map.schema.json`
- Lists every source the compiler will read
- Assigns priority order without ambiguity
- Resolves or surfaces every conflict
- Flags every fabrication risk for Pass 5
- Marks no `unsafe` source as usable

If any of the above fails, Pass 2 has not completed.
